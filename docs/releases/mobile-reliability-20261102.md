# スマホ操作・送信受付・単発当選の改善（0.10.0）

商品情報を修正して元の確定ボタンを押しても、編集後の値を保存する。仕分け後は現在のタブと作業位置を保つ。商品名は全角約14文字の幅に収め、タップで全文を確認できる。カードの「振分・削除・表示名・内容」は横1段に配置する。

URLの受信保存が完了した時点で受付結果を返し、解析キュー待ちを分離する。保存前に成功を返さず、再送時は同じ受付IDの結果を返す。同期の不正な成功応答、恒久失敗の自動再試行、無関係な商品の滞留を防ぐ。

キャンペーン名がない当選は、振分画面の「単発当選として登録」から作成する。確認したURL集合を固定し、Alignが配置対象外のcampaign_idを、Vaultが商品と割当・収益の原本を保持する。既存のチリツモ・TikTok・暫定保管の区別を維持する。

## 公開条件と範囲

- 利用者の2026-11-02指示により、7担当による改修・独立確認・本番反映を実施する。
- `mobile-reliability-reviews.json`に7つの独立判定と確認済みソースのSHA256を固定する。
- Alignの単発登録契約を先に公開する。
- Vaultでは`0015_single_wins.sql`の受付テーブル・2索引と移行記録のみを追加する。業務URLの削除・全DB復元は行わない。
- 既存サービス・DB・キュー・cron・公開範囲を事前照合し、専用`ALIGN_SINGLE_WIN`接続だけを加える。
- 公開後は配信Workerと画面資産のバイト、認証、schema、既存接続設定を照合する。復旧時も他者の同時変更を上書きせず、新しい受付テーブルを残す。

## 検証

候補CIの画面検査は320/360/393/412 CSS px、通常文字と拡大文字を含む。実際のページ・API操作・サービスワーカーの確認は、抽出した描画関数による表示試験と分けて行う。異常系は別担当が作成した。候補CI 41428411439（source f7838cc6790f22b74824979745a902c028c2c4a7）で196件のコード試験、Cの100表示条件、Gの13実ブラウザ条件と静的PWA依存検査、既存削除3幅、公開ガード9＋5件、dry-runが成功した。7担当の独立判定はすべてPASS。物理Pixel 10と本番公開証拠は別に扱う。

Androidの対応版はcode62 / v0.3.8-winning-share-receipt。候補CI41422469968の185件が成功し、既存署名による公開は共通基盤の別工程で行う。物理Pixel 10での操作と実ネットワークの複数台計測は、合成試験やビルド検証とは区別する。

不正な既存商品情報は、単発campaignの作成前に具体的な理由で停止し、原本を自動修正しない。登録途中で対象が変わった場合の空のAlign campaignは、自動削除せず元URLと割当の整合を優先する。

## 公開前照合の訂正

初回本番CI41429970313は、共通helperの候補ハッシュとrepo実体の不一致で変更前に停止した。取得時のローカル控えに末尾の空行が1つ多く、Python ASTは完全に同一だった。repoの実体ハッシュへ記録を訂正し、厳密なバイト照合を維持して再実行する。アプリ・helperの実行コード・検証条件は変更しない。
